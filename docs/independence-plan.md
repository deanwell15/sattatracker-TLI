# Deanfinite: следующие этапы независимости

Deanfinite — независимый форк SattaTracker; репозиторий пока остаётся
`deanwell15/sattatracker-TLI`, исходная атрибуция sattatrapy/MIT сохранена.

## 1. Принятая идентичность

Название **Deanfinite**, identifier **io.github.deanwell15.deanfinite**,
package **deanfinite**, library **deanfinite_lib**, binary **Deanfinite.exe**.
Publisher — deanwell15. config перенесён в собственный app_config_dir;
cache/assets/WebView отделены identifier, автоматического импорта старых данных нет.
Подробности, ограничения и Windows checklist:
[deanfinite-branding.md](deanfinite-branding.md).

Графический этап выполнен: bundled собственные заглушки, без upstream assets/Google Fonts.
[Архитектура и проверки](local-assets.md). Источник цен пока не заменён. До подтверждения новой
Windows-сборки runtime совместимость не считается проверенной. Смена identity
согласована; изменение экономической логики по-прежнему отложено.

Принадлежность IP сервера цен автору **не подтверждена**: его заменяем ради
независимости от внешнего неподконтрольного оператора. TLIDB/TITrack здесь
не объявляются подтверждёнными API рыночных цен.

Другие прикладные runtime обращения к инфраструктуре автора аудит не обнаружил.
App EXE updater отсутствует: `assets.zip` обновляет только ресурсы. GitHub npm/Cargo
downloads, инструменты CI и Microsoft WebView2 не являются авторскими сервисами.
Временные HTTP redirect/CDN-адреса нужно учитывать при сетевой проверке.

### 2.1. Архитектура цен с заменяемыми поставщиками

Сохранить внешние методы `PricingManager` для FSM/tailer. Добавить контракт
`PriceProvider`, возвращающий нормализованный `PriceSnapshot`:

- `provider_id`, `season_id`, контекст рынка/региона при необходимости;
- валюта и единицы (`FE`), время получения и срок актуальности;
- стабильные игровые ID и цены, версия схемы, происхождение данных.

План providers:

1. Совместимый адаптер текущего API — временно для сравнения и отката.
2. **Локальный JSON/import provider** — работающий контролируемый offline-путь;
   данные должны иметь известное происхождение и покрытие нужного сезона.
3. Собственный HTTPS snapshot endpoint — если выбран и подтверждён источник.
4. Потенциальные адаптеры TLIDB/TITrack — только после отдельного исследования.

Наличие сайта/каталога предметов не означает наличие рынка. Для каждого кандидата
проверить документированный API или разрешённый экспорт, условия использования,
право перераспространения, сезон/регион, matching ID, единицы и агрегацию цены,
freshness, rate limits и полноту. Не внедрять scraping/auth обходы и не считать
примерные/исторические цены актуальными. Если кандидат даёт только item catalog,
использовать его лишь в этом качестве после проверки прав.

Общий валидатор: корректный статус/JSON/schema, ограничение размера, только
конечные неотрицательные цены, проверка валюты/сезона, явный статус устаревания.
Кэш: namespace по provider+season+market, атомарная запись, last-known-good,
контролируемый TTL. Дополнительное разделение cache по provider/season согласовать перед реализацией.
Текущее `TLI_PRICE_API_URL` сохранить как совместимый override на переходный период;
конкатенацию query заменить структурированным URL builder.

Сейчас не менять финансовые формулы, налог, фильтрацию, parser или пересчёт
прошлых drop. Их известные дефекты остаются отдельным этапом.

### 2.2. Ресурсы и права

**Не копировать** чужой `assets.zip` в форк или публичные артефакты до установления
прав на его содержимое. MIT исходников не доказывает права на игровые изображения,
анимации и сторонние шрифты.

Выполнено в графическом этапе: перечень использования, собственные нейтральные
SVG/иконки приложения, fallback вплоть до CSS, запуск без ожидания графики,
удаление upstream загрузок и всех трёх asset-команд. Файловый asset protocol
полностью отключён, getIcon/getAnim сохранены, старые пользовательские файлы
не удаляются. Архив не скачивался и не публиковался. Детальные игровые изображения
и прежние покадровые анимации заменены статическими заглушками.

Далее при необходимости — собственный расширенный набор/анимации с реестром прав.
Удалённое обновление графики сейчас не требуется и не реализовано.

### 2.3. Переход без потери работоспособности

Каждый новый provider/resource path сначала проверяется отдельно на fixtures и
Windows, затем включается для тестового профиля. Существующие механизмы остаются
до готовности замены. Параллельное сравнение не должно повторно начислять loot.

После подтверждения замены удалить авторские URL и автоматические fallback к ним;
провести поиск строк и сетевую проверку чистого запуска, refresh, error recovery и
отдельного окна. Иначе отключённый основной путь с fallback не обеспечивает
независимости. На каждом переходе проверять, что старое приложение/данные сохранены.

2. Завершить Windows GUI checklist bundled-графики; исходные анимации заменены
   нейтральными заглушками, автоматические upstream загрузки удалены.
3. Исследовать локальное получение рыночных цен: уже доступные логовые сведения,
   разрешённые импорты, подтверждённые кандидаты providers и локальный кэш. Не
   считать TLIDB/TITrack доказанными источниками и не обращаться к памяти игры.
4. После работоспособных замен удалить upstream endpoints/fallback, проверить сеть,
   затем собственные подписанные релизы. Не публиковать Release автоматически.
5. Ошибки статистики и изменения parser — отдельные последующие задачи.

Существующие сетевые механизмы не отключать до проверки полноценных замен.
