# Цены и учёт лута Deanfinite

Статус: **Automatic (TITrack) включён**, по подтверждённой пользователем
Windows live-проверке HTTP 200 и SS14/1601. Codex/CI не выполняли успешного live
запроса: окружение блокирует host на CONNECT. Полные детали transport, границ,
тестов и ручной проверки: [TITRACK_INTEGRATION_REPORT.md](TITRACK_INTEGRATION_REPORT.md).

## Архитектура и запуск

PricingManager управляет ценами и сезонным cache. PriceProvider отделяет потребителей
от TITrack HTTP; LocalJsonPriceProvider валидирует импорт, TiTrackPriceProvider читает
только aggregated_prices с фиксированного HTTPS host. Никаких uploads/личных поисков.

UI и трекинг не ожидают сеть. Cached snapshot публикуется до первого HTTP запроса;
Tokio spawn_blocking обслуживает HTTPS без удержания price/operation locks.
Source/season change отменяет дальнейшие страницы и применение старого результата.
300 секунд между началами нормальных обновлений, bounded timeout/backoff/Retry-After,
без немедленных повторов. Local JSON не делает сетевых обращений.

## Импорт JSON

Settings → Filter → Market prices → Source → **Local JSON** → Import local prices.
Настройка источника и импорт сохраняются сразу, независимо от кнопки сохранения
остальных настроек. Ошибка показывается в этом разделе. Импорт полностью заменяет
локальную таблицу **текущего сезона**, допускает неполное покрытие.

Пример ниже содержит **выдуманную тестовую оценку**, не реальные рыночные данные:

```json
{
  "schema_version": 1,
  "season_id": 1601,
  "currency": "FE",
  "source": "manual",
  "updated_at": "2026-10-20T08:00:00Z",
  "prices": {"100300": 1, "123456": 12.5}
}
```

Контракт: [JSON Schema v1](schemas/local-prices-v1.schema.json). Rust выполняет
эквивалентную структурную и семантическую проверку (без загрузки schema из сети):
обязательные поля, запрет неизвестных полей, версия 1, FE, совпадение сезона,
числовые ID из 1..12 цифр без ведущего нуля, конечные цены в 0..1 000 000 000,
не более 50 000 ID и 4 MiB. Источник — 1..80 UTF-8 байт без управляющих символов.
RFC3339 требует timezone; даты до Unix epoch и более 5 минут в будущем запрещены.
Для `100300` допускается только 1 FE. Отрицательные, строки вместо чисел,
NaN/Infinity/переполнение отклоняются. Невалидный импорт не меняет RAM и файл кэша.
Наличие ID в каталоге имён не обязательно: неизвестное имя не означает неверный ID.

## Хранение и offline

В собственном `app_local_data_dir` Deanfinite:

```text
prices/settings.json
prices/v1/1601/local.json
prices/v1/1601/automatic.json  # цены + cursor/full/success metadata, атомарная запись
prices/v1/1501/...           # отдельный сезон, не fallback для 1601
```

Cache v1 хранит season_id/currency и по каждому ID value/source/updated_at/received_at.
Локальный источник имеет префикс `local_json:`, агрегаты — `titrack_aggregate`.
Старый неразмеченный файл цен не импортируется и не удаляется. Запись: сначала
полная проверка, затем временный файл в том же каталоге, flush/sync_all, rename,
после успеха — замена RAM. Ошибка не заменяет прежний действующий файл/оценку.
Provider refresh проверяет все страницы, сохраняет prices вместе с sync metadata,
затем публикует snapshot. Cursor — из реально прочитанных timestamps; inclusive delta
и keyset pagination защищают границу одинакового времени. Полная сверка — раз в 6 часов.
Кэш не перечитывается с произвольного пути: пользователь выбирает JSON через UI.

Известная цена бывает **Known** или **Stale**, отсутствие — **Unknown** (`value:null`).
Настоящий 0 FE остаётся Known. После 24 часов от исходного updated_at запись Stale;
received_at/import time не омолаживает её. FE всегда 1, без срока давности.
Вывод: `[12.5]`, `[—]`, `[12.5 ≈ stale]`; подсказка показывает источник и дату.
Суммы — оценка по доступным ценам, Unknown не считается подтверждённым нулём.
Автоматический режим использует cloud primary (в том числе явно Stale);
локальная таблица заполняет только отсутствующие cloud ID. Local JSON не использует
таблицу Automatic. Смена режима пересчитывает имеющиеся предметы.

## Сезоны

Явная целевая настройка при отсутствии лога — SS14 Tartarus, 1601. Из лога берётся
последнее корректное поле `+player+SeasonId [...]` / `+SeasonId [...]`, а не первый
случайный bracket в строке; при живой смене поля переключается пространство кэша.
Исследованная таблица соответствий: **Deanfinite 1601 → TITrack 1601**. Для других
сезонов TITrack adapter отказывает до добавления подтверждённого mapping.
Это совпадение форматов проверено в исходниках TITrack, но наличие живых цен не
доказано. Новый сезон не получает SS14-кэш. Уже записанные дропы имеют season_id,
поэтому новые котировки переоценивают только записи соответствующего сезона.

## Количества, порог, переоценка

Каждый корректный LootDrop учитывается независимо от цены/порога. Карта и сессия
получают независимые объекты: общий объект раньше приводил к двойному увеличению
количества при повторном дропе. `sessionLootCount` увеличивается один раз.

Min Drop Value фильтрует **только LootFeed и эффекты будущих событий**. Feed применяет
его к текущей суммарной оценке агрегированного ID/сезона. Понижение порога показывает
сохранённые записи сразу; ItemsHistory всегда содержит все учтённые предметы.
Unknown виден в feed при пороге 0, но не запускает ценовые эффекты.
Настройки исключения аукционных событий и Block item не заменяются этим фильтром.

Новая таблица цен переоценивает весь лут активной сессии и текущей карты раздельно.
Изменение session subtotal прибавляется к totalProfit; изменение map subtotal —
к currentMapProfit. Нельзя складывать обе разницы в totalProfit. Количества,
таймеры, число карт, latestDrop и анимации не изменяются.
Для налога сохраняется сумма налоговых весов по количеству каждого дропа:
переоценка не переписывает настройку налога, применённую к прошлому дропу; FE exempt.
Округлённая учтённая сумма хранится отдельно от удельной цены, чтобы переоценка
не оставляла копеечный остаток от округления отдельных поступлений.

Расходы и mapCost сохраняют оценку момента записи и не переоцениваются.
Инвентарный snapshot переоценивает свои количества отдельно; существующая модель
inventoryValue с добавлением новых дропов и редкими sort snapshot не переработана.
Независимые известные дефекты resetSession/mapCost, классификации расходов,
граничного восстановления логов и смены карты с тем же level_id остаются за рамками.
Эти ограничения требуют отдельной задачи и не маскируются тестами цен.

## Проверки и Windows

Локально пройден 32 Rust unit/integration сценариев по реальным исходным модулям
без Linux GUI: JSON, atomic write errors, unknown/zero/stale, сезоны, источники,
fixture TITrack, parser → FSM → сериализованный LootDrop, сохранение auction exclusion.
Это не нативная компиляция Tauri: Linux GTK/WebKit не установлены.
Также пройдены 9 Pinia сценариев, TypeScript, production frontend с 243 кадрами,
6 Chromium сценариев clean/restart/offline/missing/corrupt/widget с настоящими
Vue компонентами и mock Tauri IPC. Browser smoke проверяет неизвестный лут,
порог, повторное количество, переоценку без нового эффекта, смену карты,
отображение ошибки Automatic и импорт через UI. Действительную валидацию JSON
проверяют Rust tests, не JavaScript mock. Отдельные 3 теста упаковки EXE сохранены.

Windows workflow `windows-test-build.yml` запускается новым PR и вручную.
Он использует Windows 2022, pinned toolchain/Node, lock files; выполняет frontend,
`test:pricing`, browser smoke, Tauri build MSI+NSIS, полный `cargo test --lib`,
проверку original icons в обоих установщиках и standalone kit.
Результат workflow не выводится из факта локальных тестов: проверяйте
[Actions этой ветки](https://github.com/deanwell15/sattatracker-TLI/actions/workflows/windows-test-build.yml?query=branch%3Afeature%2Fdeanfinite-pricing)
и статус нового PR. Динамический итог и run URL записываются в отчёт артефакта.

Вручную на Windows:

1. Сохранить старую установку и проверить новую сборку отдельным запуском.
2. При отключённом интернете запустить overlay и игру: UI/трекинг доступны.
3. В Local JSON импортировать собственную таблицу SS14; проверить источник,
   сезон 1601, count, дату, повторный запуск и сохранённые значения.
4. С положительным Min Drop Value подобрать неизвестные маяки/материалы:
   история и количества увеличиваются; понижение до 0 показывает `[—]` в feed.
5. Повторно подобрать тот же ID; карта/сессия увеличиваются ровно на пришедшее qty.
6. Импортировать изменённую цену для уже учтённого ID: оценка обеих областей
   меняется, количество/анимации/число дропов не меняются.
7. Невалидный JSON, SS13 вместо SS14, отрицательные значения, неверный FE:
   понятная ошибка, предыдущая таблица остаётся после перезапуска.
8. Automatic получает cloud prices; Local JSON не делает HTTP. Проверить offline/error/cooldown.
9. Проверить оригинальные иконки/анимации в main и pop-out без сетевых загрузок.
10. HTTP 200/SS14 подтверждены пользователем; новую версию приложения проверить вручную. Квота сервера не предполагается неограниченной.
